WordPress + API基盤 + 生成AI(LLM) 導入提案

前提: WP=1万PV/月, Cloud Run=1万req/月 / 最安構成の比較と推奨

結論（おすすめ構成）

BConoHa WING + Cloud Run を推奨します。

  • 自動バックアップ（14日）が標準で、復旧が簡単
  • 月額は ¥660 + $0 + ($1.3〜$5) のレンジで予測しやすい
  • APIはGoogleの無料枠（Cloud Run）を活用し低コスト
  • キャンペーン終了後は通常料金に上がる可能性

補足: 最安重視ならA、ゼロ課金挑戦ならC1、統一運用ならC2/Dが適します。

目的

  • 最安〜省力運用までの実現可能な選択肢を比較
  • 運用負荷とコストのバランスが取れた推奨案を提示
  • 初期導入から安定運用までのロードマップを明確化

前提・定義

  • Always Free: クラウドの無料利用枠（毎月）
  • 生成AIの費用目安: 10k回の呼び出しで軽量（入500/出200 tokens）≈ $1.3、中量（入1k/出1k）≈ $5
  • Cloud Runは無料枠内想定（実トラフィックで変動）
  • レンタルサーバー＝低価格の共有サーバー（管理は事業者が実施）
  • サーバーレス＝使う時だけ自動で動く実行環境（従量課金）
  • マネージド＝日々の運用（更新/故障対応等）をクラウドが担う

推奨構成（用途別）

最安重視

A（必要に応じて自動バックアップ +¥440）— 数百円 + 数ドルの運用レンジ。
  • 前提: PV/reqは小規模、停止リスクは許容
  • WAF/SSLは提供に依存、改ざん監視は軽量導入

運用省力

B（自動バックアップ標準/復旧手順が簡単）。
  • 障害時のRPO/RTOをシンプルに維持
  • 価格はキャンペーン期間後の通常料金も確認

ゼロ課金挑戦

C1（技術工数と可用性を自前で担保できるなら）。
  • OS/ミドル更新・監視・バックアップの自動化が必須
  • 負荷上昇時はC2等へスムーズに移行できる設計

GCP/Azureで統一

C2 / D（監視/構成管理は楽だが固定費が乗る）。
  • 共通監視/セキュリティ監視/権限管理をクラウド標準に統合
  • コスト上振れには上限/予算アラートを併用

リスクと対策

セキュリティ

  • WAF/SSL: 共有サービスの設定確認と最小化方針
  • WordPress: 最小権限・不要プラグイン排除・自動更新
  • API: 認証・レート制限・WAFでの攻撃遮断（SQLインジェクション等）

バックアップ/復旧

  • ファイル/DBの世代管理（最短日次）と復旧手順の検証
  • 運用省力重視はBを選択（自動バックアップ14日）

スケール/コスト

  • 無料枠超過の上限設定と予算アラート
  • LLMは入出力トークン増で逓増：プロンプト設計最適化

可用性

  • C1はSPOF/運用負荷を許容できる場合のみ
  • 可用性優先はC2/D（マネージドDB/スケール設計）

導入ロードマップ（例）

  1. 要件確定・構成選定（A/B/C1/C2/D）
  2. ドメイン/SSL・監視/通知方針・予算アラート設定
  3. WordPress構築（テーマ/プラグイン方針・権限/更新）
  4. API基盤（Cloud Run）デプロイ・レート制限
  5. 生成AI連携（APIキー保護、可観測性/ログ）
  6. バックアップ/復旧演習・WAFチューニング
  7. パフォーマンス/キャッシュ最適化（Cloud CDN等）

出典・根拠（抜粋）

  • Cloud Run 無料枠: 200万 req/月・180k vCPU-s・360k GiB-s
  • GCE e2-micro Always Free: VM1台 + PD 30GB + 北米1GB出
  • Cloud SQL 料金例: vCPU $0.0413/h, Memory $0.007/GB-h, SSD $0.17/GB-月
  • ロリポ「ライト」¥264/月、ConoHa WING キャンペーン例 ¥660/月（自動バックアップ14日）
  • Azure App Service B1(Linux) + MySQL Flexible B1ms ≈ $25.5+/月
  • Gemini API: 2.5 Flash-Lite $0.10/M入・$0.40/M出、Flash $0.30/$2.50

実価格はリージョン/為替/キャンペーンで変動します。最新の公式料金をご確認ください。
