02

WHAT'S NEW

既存エージェントと何が違うか

コーディングエージェント（Claude Code / Codex / Grok Build）やチャット型エージェントとの差分は、実行環境の持続性と仕事の完遂境界にある。

BEFOREチャット / コーディングエージェント

  • 下書き・提案・PR で止まりやすい
  • セッションやツール接続が断片的
  • 人間がツール間のハブになる
  • Grok Build はターミナル上のコーディング・ハーネス

NOW · GROK BOT業務を完遂する同僚

  • ログイン済み画面に成果を置く
  • セットアップ摩擦が低く「頼む」一文から始まる
  • デスクトップ / iOS で同じスレッドを継続
  • Bot はクラウド PC 上の業務同僚（営業・運用・跨ぎアプリ）

API/MCP がある所はコネクタ、無い所は computer use。接続の綺麗さで仕事を切り捨てないのが設計思想。

COMPARE

評価は「賢い返答」ではなく、同じ画面に仕事が残るか。Build と Bot は役割分担——知能と実行環境のレイヤが分かれた。

03

ARCHITECTURE

専用コンピュータという設計

公式ドキュメントの核心は、Bot = 名前付きの持続エージェントであり、実行基盤はアカウント単位の共有クラウド PCだという点である。

ARCHITECTURE BOARD
Shared Cloud PC · 1 account boundary
Chief of Staff ORCH

優先度・委譲・承認ゲート。人間へのエスカレーションを束ねる。

Sales Bot LIVE

CRM・メール・調査。ログインとファイルは共有 PC 上に残る。

Ops / Eng Bot LANE

入社セットアップ、請求、再現→チケット。handoff で再ログイン不要。

便利さの裏：1 Bot に渡した認証情報は他 Bot からも見える前提で権限設計が必要。
  • 各 Bot はブラウザ・ファイルシステム・ターミナルを持つ持続 VM 上で動く
  • 全 Bot が同一コンピュータを共有：ログインやファイルはアカウント境界。Bot ごとには別スクリーンだが、セキュリティ境界は分離されない
  • だから handoff が簡単：別 Bot に渡しても「もう一度ログインして」が発生しにくい

RISK

便利さの裏に「共有 PC」リスク。機密システムへの権限は段階的に、承認フローを前提に渡すのが実務の基本。

04

MULTI-AGENT

一人のハブをやめる：Bot 同士の協調

社内利用では「参謀 Bot + 専門 Bot」構成が典型例として語られる。人間がツール間の伝書鳩になる構造を、Bot 間メッセージで置き換える。

  • 並列実行：inbox / 経費 / 採用 / バグ修正などレーン別に Bot を分ける
  • スレッドとグループチャットで文脈共有・オーナーシップ委譲
  • 判断が要る所だけ人間を呼ぶ（approval gate）
  • 事例：営業 Bot が CRM 更新とフォロー下書き、ops Bot が入社セットアップと請求書処理、engineering Bot が UI 再現→チケット→デバッグ Bot へ

SHIFT

評価軸は「賢い返答」からチームとしてのスループットへ。オーケストレーション自体をプロダクトが引き取る。

06

USE & ACCESS

誰が使えるか、どこから試すか

公開時点のアクセスは SuperGrok Heavy、Cursor Ultra、Cursor Teams Premium（デスクトップ / iOS）。Enterprise は waitlist。

  • 向く仕事：複数ツール横断・明確な成果物・翌朝までに欲しい調査/下書き/衛生タスク
  • 公式が示す一例：Salesforce の見込みリスト抽出→既存シーケンス除外→上位アカウント調査→LinkedIn/メール下書きを朝までに承認待ちで用意
  • 注意：共有 PC 上のログインは全 Bot 共通。セキュリティと承認設計を先に読む（docs: approvals / security / privacy）
  • 一次情報：Introducing Grok Bot · Docs overview

Security note: 共有クラウド PC では認証情報がアカウント境界で共有される。機密システムへの権限は段階的に、approval gate を前提に渡す。

BOTTOM LINE

Grok Bot は「より賢いモデル」の発表ではなく、仕事が滞留しない実行環境付きチームの発表である。エージェント競争の主戦場が、知能単体から運用スループットへ移った合図として読む。

TAKEAWAY

エージェント競争の主戦場は、モデルの賢さから「同僚に仕事を渡せる実行環境」へ移った。
Grok Bot は、チャットの続きではなく、常時稼働チームのプロトタイプだ。
