01 · MAP

まず全体像——何が「座標」を動かしたか

KEY MAP · 4 LAYERS

LAYER 01 プロダクト — Docs / Sheets / Slides / PDF + Shell。Electron 5 アプリ、共有 TS エンジン層。

LAYER 02 AI — Super Agent 内蔵。Docs は block-granular 編集 + snapshots/diffs。Sheets/Slides/PDF は tool-calling over state。

LAYER 03 忠実性 — 元ファイルを source of truth。狭いパッチ適用。DOCX は byte-preserving paragraph patch。

LAYER 04 戦略 — ローカル日常オフィス入口 → 文脈蓄積 → Genspark Agent サービスへ繋ぐ。

BEFORE → AFTER

BEFORE
AI はサイドバーやクラウド生成が中心。既存 .docx を壊さず深く編集する OSS フルスイートは実質不在。LibreOffice は成熟だが AI-native ではない。

AFTER · 2026-08-03
デスクトップで AI がドキュメント状態を直接操作。コア無料・フル OSS。Alpha だが「明日から試作」できる衝撃。

なぜサプライズか: 「チャットが上手い Office アドイン」ではなく、AI 編集を第一級市民にしたフル機能スイートをいきなり OSS で出したこと。スライド映えする「これ明日から使う」感と、既存 VisionHub エントリとの被りゼロが刺さる。

03 · WHY IT MATTERS

エンジニア / ビジネス視点の「5層のすごさ」

01AI がボルトオンではない

  • チャット箱ではなくドキュメント状態への tool-calling
  • 生成 → 手動貼付 → レイアウト崩れ、のループを短縮
  • 「プロンプト一発で会議資料」が編集器内で完結

02ファイル忠実性を技術目標にしている

  • 元ファイルを source of truth
  • DOCX は dirty 段落のみ再生成（paragraph patch）
  • 代替 Office 最大の弱点「開いて保存で崩れる」への対策

03フル OSS × 無料コア

  • Apache-2.0 で fork / 組み込み / PR 可能
  • ライセンス料・広告・透かしなし
  • 社内ドキュメント自動化の試作ハードルが低い

04入口戦略として合理的

  • Genspark ARR ~$250M 規模の Agent 企業が「無料 Office」を出す
  • 日常ワークフローに入り文脈を蓄積
  • AI クレジットが本線の収益接点

05開発プロセス自体がメッセージ

  • 1 人 × 1 週 × $10k で Alpha → 即公開
  • 完璧を待たずコミュニティと共創

+スライド映え・即導入感

04 · ARCHITECTURE · FILE FIDELITY

決定的な差——byte-preserving round-trip

Core idea
Patch, not rewrite
元ファイル = source of truth
Docs engine
paragraph patch
dirty ブロックのみ OOXML 再生成

DOCX ROUND-TRIP フロー

  1. Open
    元 .docx をハッシュでアーカイブ（直接変更しない）
  2. Parse
    document.xml → block tree · 各 block に docxIndex + 元 XML slice
  3. Edit
    TipTap 上で人間 / AI 編集 · dirty tracking
  4. Save
    dirty のみ OOXML 化 → splice · 他エントリは byte コピーで ZIP 再パック

TECH STACK

Electron + React + TypeScript · 純粋 TS エンジン層（Electron 非依存）· Sheets: Univer (Apache-2.0) + Rust sidecar · Charts: Konva · PDF: pdf.js + pdf-lib · Text: HarfBuzz · agent-core / ai-provider / ai-search

AI 配線

全アプリ共通 AI パネル。モデル呼び出しは Genspark プロキシ（Claude / GPT / Gemini 系など）。ローカルに API キーを置かない。Web / 画像検索ツールも ai-search 経由。

読みどころ: マーケティングの「AI Office」ではなく、docx-engine のパッチ設計と agent-core の tool-calling が、既存の生成→貼付ツールとの技術的境界線。

4 エディタで「なにができるのか」

  • プロンプトでセクション下書き・段落リスタイル・読者向けリライト

  • 例: Nestly pitch を 1 プロンプトで 6 枚生成、という公式デモ

04PDF

  • 長契約・論文・明細を開きハイライトして質問

ビジネスモデル

コア編集は $0。研究・生成・分析など AI 機能のみ Genspark クレジット。貢献者に 1,000+ クレジット付与で Alpha 品質を加速。ee/ に Enterprise 拡張の余地。

戦略的読み

短期のライセンス収益ではなく、ローカル作業の第一入口を取り、ドキュメント文脈を Agent エコシステムに接続する。Workspace 4.0 の「Office 内 Agents」と連続する製品思想。

実務の含意: 「無料 Office 代替」として見るより、「AI エージェントが住むデスクトップ作業面」として評価した方が、機能ギャップ（Alpha）とクレジット消費の両方を説明できる。

08 · CAVEATS

サプライズしすぎないための注釈

Alpha 明示

公式がバグ・欠機能・ラフエッジを明言。本番唯一の編集器への即切替は非推奨。

忠実性は「目標」であり保証ではない

独立ガイドも複雑テンプレでの完全 round-trip は未確立と指摘。自分の代表ファイルで検証必須。

AI はクラウド依存

オフラインではコア編集のみ。ネット + Genspark アカウントが前提。本体のクレジット不透明さ・サポート課題が影響しうる。

プラットフォーム限定

現時点の公式インストーラは Apple Silicon macOS と Windows x64。Intel Mac / Linux は非対応。

「世界初」は主張

マーケティング文言。比較軸（フル機能・AI-native・OSS・デスクトップ）の定義次第。評価は機能とコードで行う。

商標・ee/

名称・ロゴは Mainfunc 商標。Apache-2.0 でも fork でのブランド流用は不可。ee/ は別 Enterprise License。

10 · THE BOTTOM LINE

今日の結論

GenOffice は「巨大 Office の完成品」ではなく、 AI-native 編集 × ファイル忠実性 × フルOSS × 無料コア入口 の四点セットで座標を動かした。追うべきは機能カタログの多寡ではなく、 自ファイルでの round-trip 実験と、クレジット付きの実務ワークフロー再現。

DO

インストーラで試す / 自ファイル検証 / Sheets・Slides を 1 プロンプト / engine を読む / フィードバックで credits

DON'T

本番唯一エディタ化 / 複雑テンプレ無検証 / オフライン AI 前提 / クレジット無視 / 「世界初」 alone で判断
