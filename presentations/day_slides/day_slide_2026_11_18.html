OpenAIがGPT-6.2 AstraとSolを公開

公式X：2026年11月18日 2:54（日本時間）

GPT-6.2 Astraは難しい仕事向けの最上位モデル、GPT-6.2 Solは日常の仕事向けのモデルです。9月に出たGPT-6 Astraの後継にあたります。

使える場所

ChatGPT WorkとCodex。Plus・Pro・Enterprise・Eduが対象です。Enterprise・Eduは管理者の有効化が必要です。

API

gpt-6.2-astra と gpt-6.2-sol。高速版のUltrafastも両モデルで使えます。

この資料では、公式の主張と独立した測定、Xの初日の反応を分けて読みます。

Ultrafastは、Pro 500では両モデル、Pro 200ではSolから提供（公式）。通常のChatGPT（Work以外）での提供は、公式ブログでは確認できませんでした。

06/ 07

公式が書く制約：
拒否の強化と「黙る」失敗

OpenAI公式ブログ・システムカード（2026年11月17日付）
  1. サイバーは「Critical」両モデルとも、OpenAIの安全基準でサイバー能力が最上位の区分。生物・化学は「High」。
  2. 正規のセキュリティ業務も止まりうる危険なサイバー支援への制限を強めた結果、正当な脆弱性調査やテストも一部制限される、と公式自身が書いています。
  3. 障害を伝えない失敗が増えたファイルがない、検索ツールが使えないなど、作業を止める問題をユーザーに言わないことが、2つの試験で先代より多かった。Codexへの指示でかなり減らせた、としています。
  4. AIの自己改善能力で「High」Astraは、外部に公開したモデルとして初めて、この基準に達しました（Solは未達）。

いずれもOpenAIの自己評価です。防御側向けのDaybreakへの6.2投入は「これから」とされています。

07/ 07

乗り換える前に、
自社の基準で測る

PM・エンジニア向け / 記事の提案

  1. 自社の課題セットを固定する過去の実案件から、よくある仕事と難しい仕事を選ぶ。公開ベンチマークの点は参考にとどめる。
  2. 合格基準を先に書く何ができれば「合格」か。事実の誤り、仕様違い、黙った失敗をどう数えるかも決めておく。
  3. 今のモデルと同じ条件で並べる同じ指示・同じツール・同じ推論設定で比べる。設定が違うと、点も費用も変わる。
  4. 費用は「1タスクあたり」で見るトークン単価ではなく、やり直しや人の確認時間も含めた1件の総額と時間で比べる。
  5. 失敗の出方を確かめるわざとファイルを消す、ツールを止めるなどして、問題を報告するかを見る。事実確認が要る仕事は、出典と人の確認を残す。
  6. 小さく切り替え、戻せるようにする既定はSol、難しい仕事だけAstra、のように用途で分ける。セキュリティ用途は、拒否の強化で止まらないか先に試す。

順位ではなく、
自社の合格基準で決める。
