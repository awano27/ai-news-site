01/ 08

使いやすい画面でも、AIには操作の手がかりが必要

開発現場の課題 / 記事の考察

人は「担当者」や「期限」を見つけ、条件を選べます。AIにも同じ仕事を任せたいとき、何が選ばれているか、どの操作が可能かをどう伝えるかが課題になります。

画像やHTMLを使う操作自動化はすでにあります。UI SDKは、それに加えて画面部品の状態とアクションを直接扱う経路を用意します。

人が操作する画面と、AIが理解して操作する仕組みを、一緒に設計する発想です。

02/ 08

Vercelが、UIの「動き」を組み合わせるSDKを公開

公式発表：2026年11月12日

UI SDKは、キーボード操作、フォーカス、選択、ポップアップなどを組み合わせるTypeScriptライブラリです。React、Vue、Svelte、Solid、Web Componentsに対応します。

見た目はアプリに合わせて整えます。入力欄や日付選択などの既製部品も利用できます。

開発を支援するAIにも、完成した画面を操作するAIにも使うことを想定しています。

03/ 08

人が使うUXは、既存の優れた画面と大きく変わらない

既存のUIライブラリ

検索して選ぶ、矢印キーで移動する、Escで閉じる。これらはすでに実装できます。

具体的な挙動は、利用するライブラリと実装次第です。

UI SDK

必要な動きを部品として組み合わせられます。検索付き選択欄などをアプリの見た目に合わせて構成します。

既存画面が自動で改善されるわけではありません。

例えば選択欄では、文字入力で候補を絞り、矢印キーで移動し、Enterで確定できます。

人向けUXの新奇さより、操作の作りやすさとAIとの接続が注目点です。

04/ 08

AIには、画面の状態と呼べる操作を渡す

公式ドキュメントの仕組み

snapshot()で部品・状態・利用可能な操作を取得し、act()で部品のアクションを呼び出します。画面上の名前を手がかりに入力値を変更する例が公開されています。

画像・HTMLを使う経路

画面を読み、対象を見つけ、クリックや入力を行う。

UI SDKの経路

部品の状態を読み、その部品が提供する操作を呼ぶ。

比較は概念整理です。既存の自動化でもDOMやAPIを使えます。速度・成功率の優位性を本記事で測定したものではありません。

05/ 08

「今日の自分のタスクを表示して」を作るなら

業務画面への応用例 / 未実装

  1. 人が依頼する「今日が期限の、自分の未完了タスクを表示して」
  2. AIが許可された条件欄を操作する担当者・期限・状態を選び、表示結果を確認する。
  3. 人が結果を見て次の行動を決めるタスクの完了や削除まで任せるかは、別に設計する。

この例には、AIとの会話、本人を判別する処理、検索APIとの連携が別途必要です。

この資料の画面図は説明用です。UI SDK単体でこの業務が自動的に実現するわけではありません。

06/ 08

AIに見せる状態と、実行させる操作を絞る

部品単位・アクション単位で、エージェントの操作を制御する仕組みがあります。まずは絞り込み条件の変更など、影響の小さい操作から試せます。

運用設計の提案

削除・外部送信・予約確定などの重要操作には、人の確認を残します。画面側の許可設定に加え、サーバー側の認証・認可と監査記録も必要です。

画面を操作できることと、業務として実行してよいことは分けて判断します。

07/ 08

既存アプリでは、1つの検索欄から試せる

導入の進め方 / 記事の提案

既存画面を一度に置き換えるより、検証用の一覧画面に検索付き選択欄を1つ作るところから始めます。AI操作は人向けの動作を確認した後に追加します。

人の操作を確認

キーボード移動、選択、Esc、操作位置の復帰、読み上げへの対応。

AIの操作を確認

正しい状態を読めるか。許可した操作だけ実行できるか。誤った対象を選ばないか。

既存のUI部品が十分に機能しているなら、全面移行を急ぐ必要はありません。

08/ 08

無料のOSS。ただしベータ版で、連携の実装は必要

2026年11月15日確認

コードはApache 2.0ライセンスで公開されています。SDKの利用にVercelの有料契約を要求する記載は確認していません。AIモデルやホスティングの料金は別です。

現在はベータ版で、APIや挙動が変わる可能性があります。既存画面の自動変換、チャット機能の自動追加、すべてのAIからの操作を保証するものではありません。
