01The Shiftタスク → アウトカム

役割の再定義：道具から、
成果に責任を持つ「同僚」へ。

仕事の最小単位は、個別の作業を指す「タスク」から、ビジネス価値に直結する「アウトカム（成果）」へ完全に移行した。AIはもはや受動的な道具ではなく、成果にコミットする「最強の同僚」として地位を確立している。

主導権の移動。 人間が逐一命令する運用から、AIが自律的にコンテキストを理解して動く運用へ。アウトプットは「テキストやコードの断片（静的）」ではなく、公開済みの『動く』アプリ・環境（動的）になった。

価値の再定義。 もたらされるのは単なる作業時間の短縮ではなく、意思決定スピードの劇的な向上。業務成果物は「共有されるだけのファイル」から、次章の新機能 Sites によって「即座に操作可能なアプリ」へと昇華する。

技術の民主化は、もはや予測ではなく不可逆な現実だ。ビジネスとテクノロジーの境界線は、この6月に消失した。

02Core · Sites静的資料 → Living Hub

「Sites」：静的資料を、
操作可能な〈Living Hub〉へ。

新機能 Sites は「インフラの消失」を具現化する。自然言語のプロンプトから Cloudflare Workers 互換コードが生成され、OpenAIが管理するセキュアな環境へ即座にデプロイされる。リレーショナルDB D1 とオブジェクトストレージ R2 のネイティブ統合が、アプリに「永続性」と「実用性」を与える。

「死体」から「生きた拠点」へ。 これまで PowerPoint という「過去のデータの死体」 で行われていた会議は、変数をリアルタイムで操作し未来をシミュレーションする 「Living Hub」 での議論へと変貌する。Sitesは単なるWeb制作ツールではない。

統制されたデプロイフロー。 細かな修正を繰り返す「保存（Save：下書き・内部レビュー用）」と、チームや組織へ共有する「本番デプロイ（Deploy：URL発行）」が明確に分離され、自由度とガバナンスを両立。エンタープライズ級のワークフローを担保する。

Living Hub · Use CasesD1 / R2
  • ▸シナリオプランナー — 財務モデルの数値をボード会議中に操作し、利益影響を即座に可視化。
  • ▸営業ダッシュボード — 地域・商材別にリアルタイムでドリルダウンし、次アクションをその場で決定。
  • ▸顧客専用ポータル — 進捗・未解決課題・次アクションを顧客と共有・更新する共同作業空間。
  • ▸永続性 — D1（DB）＋ R2（ストレージ）で、デモではなく実運用に耐える。
Living Hub = Prompt → Sites + D1 + R2 + Deploy

04Annotations指して直す · 数日 → 数分

画面を「指して直す」、
ユニバーサル・エディター。

生成物が完璧であることは稀だ。Annotations は、AIの出力に対し人間が画面上の特定箇所を指定して修正指示を出す、極めて直感的なフィードバック体験を提供する。スクリーンショット・DOMセレクタ・構造メタデータを組み合わせた「マルチモーダル・グラウンディング」技術が基盤だ。

「全体を指示し直す」の終わり。 「このチャートのラベルを明確に」「このボタンをブランドカラーに」——非効率な全体プロンプトを排し、ピンポイントの修正を可能にする。Sitesだけでなく、ドキュメント・スプレッドシート・スライドまで拡張されたあらゆる成果物の「ユニバーサル・エディター」として機能する。

定量的な効率化。 従来の「指示 → 生成 → 確認」という数日単位のフィードバックサイクルを、数分単位へと短縮。成果物の完成度を高めるスピードが劇的に加速する。

1

指す

画面上の対象を直接クリック／囲む。

2

伝える

「ここをこう」と短い自然言語で指示。

3

接地

SS＋DOM＋メタデータで意図を厳密に特定。

4

反映

該当箇所だけを再生成。数分で確定。

05Enterprise GovernanceAWS Bedrock · RBAC

全社導入の信頼性：
Bedrock × RBAC。

企業がCodexを全社展開するための信頼性確保として、強固なガバナンス体制が構築された。鍵は AWS Bedrock 統合と、役割ベースのアクセス制御（RBAC）の二本柱だ。

セキュリティの黄金律：Bedrock 統合。 Amazon Bedrock との統合（GovCloud対応）により、医療や金融など極めて高い機密性が求められる業界でも、既存のAWS運用・認証・請求環境下でCodexを安全に利用できる。CISO（最高情報セキュリティ責任者）が求める厳格な統制をクリアする決定打となる。

役割ベースのアクセス制御。 管理者（Admin）は、サンドボックスから本番環境までのフローを完全にコントロールできる。誰がどのプラグイン（Salesforce等）にアクセスでき、誰がSitesを公開できるかを厳格に定義する。

Governance ControlsRBAC
  • ▸Bedrock 統合 — GovCloud対応。既存のAWS認証・請求下で安全に運用。
  • ▸権限の最小化 — プラグイン単位・公開権限単位で厳格に定義。
  • ▸公開範囲の制御 — 作成者限定／ワークスペース全体／カスタムグループの階層別設定。
  • ▸統制フロー — サンドボックス → 本番までAdminが完全管理。
機密業界

医療・金融でも既存AWS環境のまま導入。データ越境リスクを回避。

最小特権

プラグインアクセスと公開権限を職務に応じて細分化。シャドーAIを抑止。

監査性

サンドボックス〜本番のフローを一元統制し、誰が何を公開したかを追跡。
