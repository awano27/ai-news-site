Claude Code

Claude Code の構築手順

Claude Code は、設定を増やすよりも、最初の共有文書を短く作ることが重要です。

Step 1

/init を実行する

最初に初期メモリを作ります。生成された内容はそのまま使わず、あとで短く整理します。

Step 2

CLAUDE.md を短くする

書くのは `目的` `主要コマンド` `重要ファイル` `禁止事項` `完了条件` の5つだけで十分です。

Step 3

1つの実タスクで試す

新機能追加でもバグ修正でもよいので、実際の仕事1本で評価します。最初から複数タスクで試さない方が安全です。

Step 4

繰り返す依頼だけ command 化する

レビュー、バグ修正、要約など、毎回同じ指示をしているものだけを command にします。

Step 5

必要になったら hook / MCP を足す

整形、自動通知、GitHub 連携などは、使いどころが見えてから追加します。最初から全部つなぐ必要はありません。

Claude Code の最小構成

  • CLAUDE.md
  • docs/ に設計メモ
  • 必要なら .claude/commands/

やらない方がいいこと

  • CLAUDE.md を長くしすぎる
  • 最初から hooks と MCP を全部入れる
  • ログだけでデバッグしようとする

Codex

Codex の構築手順

Codex は、単独で使う前提より、役割分担しやすい形にする方が効果が出やすいです。

Step 1

CLI か App を決める

まず CLI で始めるか、複数タスクを回すために app を使うか決めます。小さく始めるなら CLI で十分です。

Step 2

AGENTS.md を作る

ここには細かい説明ではなく、`何のリポジトリか` `どの docs を読むか` `主要コマンド` だけを書きます。

Step 3

詳細は docs に分ける

設計、レビュー基準、運用ルールは docs/ に分けます。AGENTS.md は目次のまま保ちます。

Step 4

役割を分ける

実装、レビュー、テスト観点整理のように役割を分けると、Codex の並列運用がしやすくなります。

Step 5

繰り返す仕事を skill 化する

レビューや要約のような routine work は、毎回長文で指示せず、同じ型にまとめる方が安定します。

Codex の最小構成

  • AGENTS.md
  • docs/ に設計・運用ルール
  • 必要なら skills/ 相当の定型手順

やらない方がいいこと

  • AGENTS.md を百科事典にする
  • parallel 前提なのに全部1スレッドで回す
  • routine が固まる前に automation 化する
