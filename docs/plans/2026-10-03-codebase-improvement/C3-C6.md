## C3 の最終契約

`src/auto_collect/main.py` は、必須フェーズ `report_text`、`archive`、`html_report`、`daily_news` と任意フェーズ `og_image` を個別に記録する。アーカイブ更新はファイルの存在だけで成功扱いにせず、サブプロセス終了コードを確認する。各生成物は実行前の size / mtime / SHA-256 と比較し、同日ファイルが残っているだけの状態を `fresh=false` として拒否する。

実行結果は `public-pages/api/auto_daily_report/run/YYYY-MM-DD.json` へ一時ファイル経由で原子的に保存する。主要フィールドは次のとおり。

- `schema_version`: 現在は `1` のみ
- `date`, `run_id`, `started_at`, `completed_at`
- `phases`: 必須/任意と成功状態
- `artifacts`: path / phase / required / exists / fresh / valid / size / mtime_ns / sha256
- `failure_count`: 任意を含む全失敗フェーズ数
- `required_failure_count`: 必須失敗フェーズ数
- `publication_ready`: 必須失敗が 0 の場合だけ true

`src/auto_collect/output_validation.py` を生成側と公開側で共有し、鮮度とハッシュだけでは検出できない不正な生成物も拒否する。

- 必須ファイルは非空
- JSON は構文解析可能
- report/API/Daily News JSON の日付が対象日と一致
- HTML の `meta[name="report:date"]` が対象日と一致
- 当日 archive JSON に items があり、archive index に当日 JSON が含まれる
- daily report の index/searchable に当日 HTML が含まれる
- 入力本文の先頭日付が対象日と一致

`scripts/publish_daily_report.py` は、同じ `run_id`、既知の必須フェーズ、失敗件数、publication readiness、全必須 artifact の valid/fresh/size/mtime/SHA-256、内容契約をステージ前に再検証する。rebase 後の再試行でも同じ検証を行う。PowerShell runner と cloud fallback は、生成と公開へ同一 run ID を渡す。

## C6 の最終契約

`scripts/publish_image2_day_slide.py` は、直接公開するファイルを `git_files()`、途中処理と finalizer が触り得るファイルを `transaction_files()` として分離した。後者には `index.html`、`feed.xml`、既存の全 day slide、`presentations/day_slides/meta_index.json` を含む。

- 非 dry-run の書き込み前に、既存ステージを拒否する。
- `--stage` / `--commit` / `--push` の場合は、transaction 対象に追跡済み変更、未追跡、ignore 済みの既存ファイルがあれば書き込み前に拒否する。
- 書き込み前に transaction 対象を byte snapshot し、書き込み例外、finalizer 非 0、検証失敗で既存内容を復元し、新規出力を削除する。
- Git へは直接出力と、この実行で変更された secondary output だけを追加する。無関係な dirty/untracked ファイルは追加しない。
- finalizer は実行中の Python に import せず、対象リポジトリの `scripts/finalize_day_slide.py` を別プロセスで読み込む。`--repo-root` が別 checkout の場合も元 checkout の ROOT を使用しない。
