## 2. 今回の作業に関係する制約（変更不可）

### トップページ `index.html`
- h1 `#heroIdentity`（「AIの動きを追い、実装と根拠を確かめる。」）はサイトの価値説明として固定。文言も要素も変えない

## 3. 依頼タスク（この順で）

### タスク 1: スライド title / description の規則化と 9 月 18 本のリライト案

1. 規則を定義する
   - `<title>` 形式: `{twist} ｜ {固有名詞 1〜3 語} ｜ VisionHub AI NEWS`。twist は h1 と同一文言。全体 60 文字以内。先頭 30 文字以内に固有名詞が 1 つ入る
   - description: 80〜120 文字。固有名詞・数字・結論を含む。本文にある事実のみ。日付は含めない
2. 9 月 18 本すべてについて、該当ページを読んでから新 title と新 description を作る。
   出力は表（日付 / 新 title / 文字数 / 新 description / 文字数 / 採用した固有名詞 / 根拠にした本文箇所の引用 20 字以内）
3. 自動化ルールを書く: description、eyebrow（h1 直上の英字ラベル）、本文の h2 から固有名詞を抽出する優先順位と除外語（「AI」「モデル」「発表」など単独では使わない語）。`inject_seo_meta.py` に実装する前提で、擬似コードで 30 行以内

### タスク 2: ハブ記事 5 本の更新ドラフト（出典必須）

優先順: `claude-models-2026` → `ai-model-comparison-2026` → `claude-code-guide-2026` → `mcp-complete-guide` → `ai-funding-2026`

各ハブについて:
1. 現行ページを読み、古くなった記述を洗い出す
2. 変更表を作る（セクション / 旧記述 / 新記述 / 出典 URL / 取得日時）。出典は公式ドキュメント・公式ブログ・公式価格ページ・SEC 開示のみ。二次記事は不可
3. 変更が 3 か所以上あるセクションは、そのセクションの全文ドラフトを書く
4. 各ハブの新しい `<title>`（60 文字以内）と description（120 文字以内）を提案する
5. 各ハブ末尾の「関連する最新スライド」として、9 月のスライドから 3 本を選び URL とその理由を書く
6. 「毎月更新」「四半期ごとに更新」の表記をどう扱うか（維持 / 「最終更新日のみ表示」に変更）を提案する

価格・モデル名・コンテキスト長・上限値は公式ページで確認できたものだけを書く。確認できない場合は「未確認」と書き、推測で埋めない。

### タスク 3: トップの入口改善（0 章の既定は「併置」）

1. ヒーローに「今日のスライド」カードを併置する仕様を 3 案出し、推奨 1 案を選ぶ。
   各案は要素構成（カバー画像 `presentations/day_slides/images/MMDD/cover.jpg`、twist、日付、CTA）、
   置き場所（肖像の位置 / ボタン列の直下 / 5秒バーの拡張）、モバイルでの折り返し、受け入れ基準への適合見込みを書く
2. 推奨案の HTML / CSS スニペットを書く。既存トークンを使い、追加 CSS は 40 行以内。
   自動更新される値は既存 id（`#heroTwist` `#heroWhy` `#heroSlideBtn` 等）を再利用するか、新 id を提案し `update_home_fallback.py` で埋めるべき値を明記する
3. ナビの最終案（6 項目以内。同一ページ内アンカーではなく実 URL）と、フッターの購読導線（RSS `feed.xml`、X、ニュースレター仮置き）
4. タグライン統一案を 3 つ出し、推奨 1 つを選ぶ。対象はトップの `<title>` と OG、About の title、README。h1 は固定なので対象外
5. 実績数値（スライド本数・ニュース件数・連続更新日数）の算出元と表記ルール。
   算出元候補: `public-pages/news/archive_index.json`、`presentations/day_slides_index.html`、`presentations/daily_reports/index.json`

### タスク 4: 英語ニュースの日本語要約の仕様とサンプル

1. https://visionhub.jp/news/latest.json を読み、英語アイテム 10 件について 1〜2 文の日本語 `blurb` を書く。
   40〜80 文字、固有名詞と数字を保持、出典名は含めない、原文に無い断定はしない
2. 要約生成プロンプト（system と user のテンプレート）と、品質チェック規則（禁止事項、固有名詞の照合、失敗時は `title` をそのまま使う）を書く
3. トップの「今日のスコア上位 3 本」でランキング 1 位に自サイトのスライドが固定表示される現状について、表示ルールの変更案を 1 つ提案する

### タスク 5: 内部リンクの設計

1. 各スライド末尾の「関連スライド 3 本」の選定ルール（同一固有名詞 > 同一カテゴリ > 日付近接）と、9 月 18 本での適用例
2. 固有名詞・カテゴリ → ハブ URL の対応表（例: Claude Code → `claude-code-guide-2026`、MCP → `mcp-complete-guide`、資金調達 → `ai-funding-2026`）
3. 既存の `build_internal_links.py`（5 ハブ + 月次ダイジェストの固定リンク）を置き換えるか、追加するかの方針と理由
4. スライド末尾ブロックの文言と HTML スニペット（既存のフッター直前に置く前提。CSS はスライド既存のクラスを使う）

## 4. 出力形式

- すべて日本語。見出しはタスク番号ごと
- 先頭に 10 行以内の要約（各タスクの成果物の所在）
- 表は Markdown 表。コード・差分・スニペットはコードブロック
- 事実には出典 URL と取得日時を付ける。未確認は「未確認」と明記し、数値・価格・モデル名を推測で作らない
- 第 1 ラウンドの成果物と重複する内容は再掲しない
- 長くなる場合は、タスク 1 と 2 を先に出力し、3〜5 は続けて出力する（分割可）
