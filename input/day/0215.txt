### 最適なワークフローの要約：「思考」と「実行」の分業

これら3つのツールは競合として置き換えるのではなく、**「思考・設計」「瞬発力」「運用・自動化」**の3層に分けて組み合わせるのが最もROI（投資対効果）が高い運用法です。

#### 1. 役割分担（3層モデル）
*   **Claude Code / Codex（脳・品質担当）**
    *   **役割:** 仕様策定、難しい設計判断、PR作成前の最終品質レビュー。
    *   **強み:** 文脈理解が深く、複雑な意思決定において品質が高い。
*   **GitHub Copilot（手元の加速器）**
    *   **役割:** IDE内でのリアルタイムなコード補完、単一ファイルの高速記述。
    *   **強み:** 開発者の「フロー状態」を維持し、物理的なコーディング速度を上げる。
*   **Cline CLI 2.0（現場監督・自動化担当）**
    *   **役割:** リポジトリ全体への横断修正、テスト実行と修正のループ、CI/CDパイプラインでの自動レビュー。
    *   **強み:** ターミナルでの並列実行、Headlessモード（`-y`）による非対話自動化、ACPによるツール非依存性。

#### 2. 推奨される具体的ワークフロー
最も効果的なのは、**「人間とCopilotが書き、Claudeが判断し、Clineが泥臭い作業を回す」**形です。

1.  **設計・方針策定 (Claude Code):**
    *   「この機能の設計案を3つ出して」と対話し、方針を固める。
2.  **実装 (GitHub Copilot):**
    *   決定した方針に基づき、IDEで主要ロジックを実装。Copilotが細部を補完する。
3.  **自動化・横断処理 (Cline CLI):**
    *   「テストを書いて通るまで修正して」「全ファイルの型定義を更新して」といったタスクをClineに丸投げする（並列実行可）。
4.  **品質ゲート (Cline + Claude/Codex):**
    *   **PR前の自動レビュー:** `git diff | cline -y` で機械的な指摘や修正案を出させる。
    *   **最終判断:** 重大な指摘事項のみを人間（またはClaude Code）が確認する。

#### 3. 運用上の注意（ガードレール）
Cline CLI 2.0の自動化機能（`-y` フラグ）は強力ですが、暴走リスクがあるため以下の制御が必須です。
*   **権限分離:** CI上では一時的なディレクトリ(`CLINE_DIR`)と最小権限トークンを使用する。
*   **コマンド制限:** 実行してよいコマンドをホワイトリスト化する。
*   **範囲限定:** `main`ブランチへの直接コミットを禁止し、作業ブランチに限定する。
